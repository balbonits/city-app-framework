Most rules you give an AI coding agent change nothing. City App Framework is a small kit for Claude Code that keeps the few rules that do, turns the must-nevers into hooks the agent can't get past, and lets you test your own rules against a real model.

Why it exists

An AI coding agent starts every session knowing nothing about your project or how you like to work. The usual fix is a pile of instructions. We tested that fix, and most of it doesn't work: the agent never opens some files, already follows most advice on its own, and treats the rest as optional.

So the kit does three things instead:

  • It gives the agent your project facts in one short file it actually loads.
  • It stops the agent, with hooks, at the few things that need you: new packages, deleting tests, force-pushes, deploys, and finishing with failing tests.
  • It makes corrections stick, as a test or a single line, so the next session doesn't repeat the mistake.

What we found

In September 2026 we ran hundreds of fresh Claude Code sessions against a small test app and scored each one with fixed checks, not opinions. Rules that made no difference were cut, including one from the kit's own first draft.

Did the old version reach the agent?
Mostly no. Its CLAUDE.md pointer stopped Claude from loading AGENTS.md on its own, and its universal rules sat behind a link no agent opened (0 of 25 runs).
Do "don't overbuild" and "no new packages" rules still matter?
Barely. 0 of 285 runs added a package, with or without rules, even when asked for a web server.
What still changes behavior?
A few specific lines. For vague asks: build the smallest part, then offer options. Without that line agents never offered options (0 of 5); with it, 5 of 5 did. A "write a test" line took tests from 17 of 25 runs to 25 of 25.
Did the old "when to ask" table help?
It over-corrected. Agents stopped to ask and built nothing in 3 of 5 runs.
Do lessons carry over between sessions?
Only if the next session runs into them. A journal entry: 0 of 5. One line in AGENTS.md: 5 of 5. A failing check: 5 of 5, even with no written rule.
Does a second "reviewer" agent help?
Not on small, clear tasks. The solo agent was right 15 of 16 times, and the reviewer missed the one bug while using more than the build did.
Is "describe it, get an app" still a dream?
No. A 4-sentence spec gave a working command-line app in 4 of 4 runs, about a minute each, with no framework at all.

Laws and customs

The city idea from earlier versions survives in one form. Laws are enforced; customs are advice. Anything that must never happen belongs in a law.

Laws: two hooks

Scripts Claude Code runs around every action. The agent can't talk its way past them.

  • Asks you (Allow or Deny) before a new package or deleting a test, even in auto mode. Unattended runs get a no.
  • Blocks force-pushes, production deploys and publishing.
  • Blocks any command you list in .claude/guard-rules.txt.
  • Won't let the agent finish while npm test fails or new tests are skipped.

Customs: one short file

AGENTS.md: project facts and a working agreement, read at the start of every session.

  • What the project is, its commands, layout and gotchas, filled in from the repo.
  • An 8-line working agreement. Each line is there because a test showed it changes what the agent does.
  • CLAUDE.md holds one line, @AGENTS.md, so Claude always loads it.
  • Other agents that read AGENTS.md, such as Codex, Cursor and Copilot, get the same facts.

The commands

Install the city-app plugin once, and these work in any project. The ones that run test sessions show the plan and ask before using your usage.

/city-app:setup
Installs the project files and fills in AGENTS.md from what the repo shows. With --check, it only reports what's missing.

Tested on new and existing projects, keeping what was already there.

/city-app:start
Starts an app or feature from a few sentences: writes the requirements to docs/spec.md, turns each one into a failing test, then builds until they pass.

Built demo/bookmarks-cli from a 4-sentence spec, tests first, and passed checks it never saw.

/city-app:lesson
Turns a correction into the strongest form that fits: a test, a blocked command, or one AGENTS.md line. Then logs it.

A lesson kept as a check or a line carried over 5 of 5 times; as a journal entry, 0 of 5.

/city-app:rules:test
Runs the same task with and without one AGENTS.md line, scores each run with a check, and tells you whether the line earns its place.

The parseArgs line: 5 of 5 with it, 0 of 5 without.

/city-app:rules:prune
Re-tests your saved rules without their lines, for example after a model update, and suggests cuts. You approve each one.

On the demo, it kept a rule whose result was unclear and cut one that made no difference.

/city-app:ui:check
Checks the pages you changed for accessibility problems, console errors and layouts wider than the screen, at phone, tablet and desktop sizes. --add-test puts the checks in npm test.

Found and fixed a planted button with no name in 2 of 2 runs.

/city-app:ui:baseline
Approves how the pages look now. After that, a page that looks different fails the UI check, with an image of what changed.

Saved the demo's 3 pages at 3 sizes and kept the screenshots out of git.

/city-app:ui:tokens
Fails when a color is typed out instead of coming from a design token, naming the file and line. --add-test puts it in npm test.

Turned a planted gray back into its token instead of deleting the style.

Start in three steps

  1. Install the plugin

    Once per computer:

    claude plugin marketplace add balbonits/city-app-framework
claude plugin install city-app@city-app-framework

  2. Run setup in your project

    In Claude Code, inside your project, run /city-app:setup. It adds AGENTS.md, CLAUDE.md and the two hooks, and fills in AGENTS.md from what the repo shows.

  3. Commit the files

    Every session after that, on your computer or in the cloud, starts with them.

No plugin? From a copy of the repo, node scripts/install.mjs ~/Projects/my-app adds the same files; then fill in the {{...}} parts of AGENTS.md yourself. Needs Node 22 or later.
