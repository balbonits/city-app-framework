## Recently shipped

- **`conventions/claude-code/` — Claude Code primitives convention subfolder (5 files).** Documents when and how to use Claude Code's extensibility primitives inside the framework: skills, custom subagents (the authoring pattern; the existing `conventions/sub-agents.md` covers the dispatch pattern), MCP servers, and hooks. README is the decision tree ("which primitive for which job?"). Topic docs cover format, frontmatter, anti-patterns, and notes specific to this framework. Each doc explicitly flags what NOT to convert — most existing conventions are *reference* content, not *procedure* content, and should stay as plain markdown. Subfolder pattern matches `conventions/ui-design/`. Universal AGENTS.md unchanged; pointer added to its deeper-references section. Three parallel research agents (one per primitive cluster) supplied the depth — Skills, custom subagents, MCP/plugins/hooks. Framework now accounts for Claude features; other AI environments (Grok etc.) will get their own subfolder if/when researched.

- **`examples/website/` redesigned to dogfood `conventions/ui-design/`.** Same session as the rules-collection ship. Added 4 primitive components (`src/components/ui/`: Button, Input, Card, Chip — all states encoded), semantic color tokens (success/danger/warning/info), an on-site `DesignSystem` section showing live tokens + components, a `Showcase` section with side-by-side vibe-coded vs. rules-applied URL-shortener dashboards (the literal proof the rules matter), Visual Rules subsection inside `Rules.tsx` with three before/after pairs, refreshed Hero with a stylized `AGENTS.md` product preview, type scale consolidated to 6 sizes per landing-page rule. Tooling added: **Storybook 10.3** (stories for all primitives + token displays for Color/Typography/Spacing) and **Playwright 1.59** (smoke + dual-theme screenshot capture). **Bug caught**: original `@layer tokens, theme, …` order made @theme inline's self-referencing var declarations win the cascade, resolving every token CSS var to empty — site had been shipping invisible in dark mode. Reordered to `@layer theme, tokens, …`. Build clean, 7/7 Playwright tests passing.
- **`conventions/ui-design/` — UI/UX rules collection (9 files).** First subfolder under `conventions/`. README is the AI-context summary organized by three phases (pin / generate / review); detail files cover color (4-layer system, OKLCH, dark mode), hierarchy & typography, layout & spacing, states & feedback, mobile, anti-patterns (vibe-coded tells), review checklist, and a `sources.md` for traceability. Distilled from four Kole Jain YouTube videos (transcripts pulled via `yt-dlp` since WebFetch can't see YouTube transcripts). Designed to be loaded as AI context: rules over narrative, anti-patterns first-class, phase-organized so each rule fires at the right moment in the codegen lifecycle. Next: create demos (wireframes, UX workflows, style guide, design system) to test whether Claude-generated UI actually improves with these rules in context.
- **`decision-patterns/codebase-shape.md`.** Reference doc summarizing how five FAANG/MAANG companies organize their codebases, framed around two orthogonal axes (repo: mono vs. poly; deploy unit: single vs. many) rather than the conventional "monolith vs. microservices" framing. Per-claim inline citations to primary sources, supplemented with named ex-employee accounts (Hacker News, journalism) where official documentation is sparse — particularly Apple. Recurring-patterns table grades each pattern (trunk-based dev, feature flags, continuous deploy, code review, "you build it, you run it", tooling investment) by per-company evidence quality, with explicit gaps where no source was located. Surfaced from the "Postgres replaces microservices" video discussion and the follow-up "what do FAANG actually do?" deep-dive; six sub-agents dispatched across two rounds of research.
